Fabrico is an automation engine you build like a factory. You place machines on a grid and join them with belts, and events from the outside world, such as a webhook, ride the belts as items. The same board given the same events ends in the same state on every run.

Press Play to run it, or Step to move one [tick](../reference/files/glossary/#term-tick) at a time. When the run reaches its last tick, the badge under the board shows the engine's state [hash](../reference/files/glossary/#term-hash) and the word match. ## How it works

Something happens outside the app: a webhook call arrives, or a timer fires. The app logs it as an [event](../reference/files/glossary/#term-event), and a [Source](../reference/files/glossary/#term-source) turns it into an item on the belt docked to its output. [Items and events](../concepts/) says what an item carries and how an event becomes one.

[Belts](../reference/files/glossary/#term-belt) carry [items](../reference/files/glossary/#term-item) from machine to machine, and each machine does one job with them. A Router sends an item down one of its outputs, a [Factory](../reference/files/glossary/#term-factory) runs your JavaScript on it, and a [Sink](../reference/files/glossary/#term-sink) at the end of the line sends it out as an HTTP request or records it.

The engine moves the whole board forward one tick at a time, and it logs every event and every edit with the tick it happened on. Running that log again from a saved state is a [replay](../reference/files/glossary/#term-replay), and a replay ends in the same state, with the same hash, every time.

## What it isn't yet

Fabrico hasn't reached its 1.0 release, so the way it saves boards and the way machines behave can still change between versions. There is no download yet: to run the app you build it from source, as [Install Fabrico](install/) explains. The app listens for webhooks on 127.0.0.1, the loopback address, so only programs on the same computer can send it a webhook.

When you press Apply, the app checks that a Factory's code compiles but doesn't run it, so code that compiles and then throws is accepted and faults on each item it gets. There's no library of ready-made connectors for other services: a board hears from a service through a webhook to a Source and calls one through an HTTP Sink, and any reshaping in between is a Factory's JavaScript. The app logs every event and edit and replays the log when it opens a file, but it has no control for stepping back through a run. A board runs in one app on one computer, and there's no way to spread a board across several computers.
