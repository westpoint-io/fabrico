As a board runs, the app keeps a record of everything that drives it, each entry stamped with the [tick](../../reference/files/glossary/#term-tick) it arrived on. Each webhook and each fire of a Source's timer is an [event](../../reference/files/glossary/#term-event) and goes in that record, and so does each edit you make and the answer to each call the board sends out. A save writes a copy of the board at one tick together with that record, and the two are enough to rebuild the board exactly.

The log under the board below is the closest thing this site has to the app's record. It lists each call the board's two Sinks make, with the tick and the answer: the top Sink sends two POST requests, logged as t70 and t190, and each gets its scripted answer 20 ticks later; the bottom Sink, a Debug Sink, records one item, logged as t130.

## What the app records

The app keeps two logs, each in the order things happened:

- The event log holds the events that feed the board: each webhook a Source received, each time a Source's timer fired, and the answer to each call a Sink sent.
- The edit log holds each edit you made to the board, such as placing a machine or drawing a belt.

Each entry carries the tick it took effect on. A timer fire goes into the event log the same way a webhook does, and a replay reads it back from there instead of firing the timer again. Only the work the machines do on their own stays out of both logs, because the engine works it out again from the board itself.

## What a project file holds

A save writes five things into the [project file](../../reference/files/glossary/#term-project-file), in this order:

1. A version number, which the app checks before it reads anything else.
2. The head tick, the tick you saved on.
3. A snapshot: a copy of the whole board at the head tick or at an earlier one, with each machine and belt, their settings, the items on the belts, each Factory's saved state and the random number state.
4. The event log.
5. The edit log.

The app refuses to open a file larger than <Fact id="limit.max_project_bytes" />. [Project files](../../reference/files/project-files/) lists the versions it opens and what a file leaves out.

## How the two rebuild a board

When you open the file, the app puts back the snapshot and replays the logged events and edits from the snapshot's tick to the head tick, each on its own tick. Outbound calls are muted during the replay: a Sink that takes an item there doesn't send its request again, and the answer the log already holds goes back to it on the tick it first arrived. The board then stands where the saved one did, and runs on from there.

That rests on the engine giving the same result from the same start and the same events. [Determinism and replay](../determinism-and-replay/) shows it with one board run twice.
